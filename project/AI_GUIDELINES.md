# Руководство для AI-ассистента

## Общие принципы работы с проектом

### 1. Архитектурные соглашения
- **Всегда используйте Composition API** - проект полностью на Composition API, не используйте Options API
- **TypeScript обязателен** - все новые файлы должны иметь типизацию
- **Scoped стили** - каждый компонент использует `<style scoped>`
- **Централизованная навигация** - изменения навигации только через `App.vue` и `stage` ref

### 2. Работа с компонентами

#### Создание новых экранов
1. Создайте файл в `src/views/`
2. Добавьте новый тип в `Stage` union в `App.vue`
3. Импортируйте компонент в `App.vue`
4. Добавьте условный рендеринг в template `App.vue`
5. Обработайте навигацию через `stage.value = 'new-stage'`

#### Модификация существующих экранов
- **НЕ изменяйте** базовую структуру без необходимости
- Сохраняйте существующие CSS классы и структуру
- При изменении стилей проверяйте адаптивность на разных размерах экрана

### 3. Стилизация

#### CSS соглашения
- Используйте BEM-подобную нотацию: `component__element--modifier`
- Все размеры в `px` (не `rem` или `em`)
- Цвета из палитры проекта:
  - Основной синий: `#0077ED`, `#2563EB`
  - Серый текст: `#6b7280`, `#374151`, `#1f2937`
  - Фон: `#F9FAFB`, `#ffffff`
  - Успех: `#22C55E`
  - Ошибка: `#DC2626`

#### Адаптивность
- Всегда проверяйте мобильные размеры (428px - основной)
- Используйте media queries для планшетов (768px+) и десктопов (1024px+)
- Учитывайте `safe-area-inset` для iOS

### 4. Работа с данными

#### Mock данные
- Mock-данные находятся в `src/data/` и `src/services/mockAuth.ts`
- При добавлении новых тестовых пользователей обновляйте `mockAuth.ts`
- Сохраняйте структуру существующих мок-данных

#### Состояние
- Глобальное состояние в `App.vue` через `ref`
- Локальное состояние в компонентах через `ref`/`computed`
- Избегайте prop drilling - используйте события (`emit`)

### 5. Интеграции

#### Telegram WebApp
- Всегда проверяйте наличие `window.Telegram?.WebApp` перед использованием
- Используйте `BackButton.show()` и `BackButton.onClick()` для навигации назад
- Учитывайте особенности Telegram UI (цвета, безопасные зоны)

#### Leaflet карты
- Инициализация карты только в `onMounted`
- Используйте `map.invalidateSize()` после изменения размеров
- Кастомные иконки через `L.icon()`
- Очищайте карту в `onBeforeUnmount`

### 6. Обработка событий

#### Touch события
- Для предотвращения конфликтов с Telegram WebApp используйте `.stop` и `.prevent`
- Изолируйте touch-события на специфичных элементах (например, handle для swipe)

#### Навигация
- Всегда используйте `stage.value = 'target-stage'` для навигации
- Не используйте `router.push` или другие методы роутинга
- Обрабатывайте возврат через `@back` события или Telegram BackButton

### 7. Формы и валидация

#### Ввод данных
- Используйте `v-model` для двустороннего связывания
- Для дат используйте `type="date"`, для времени `type="time"`
- Проверяйте валидность перед отправкой

#### Обработка ошибок
- Показывайте понятные сообщения об ошибках
- Используйте специальные экраны ошибок (например, `BookingErrorScreen`)

### 8. Производительность

#### Оптимизация
- Используйте `computed` для производных данных
- Избегайте ненужных ре-рендеров через `v-if` vs `v-show`
- Ленивая загрузка изображений где возможно

#### Зависимости
- Не добавляйте новые зависимости без необходимости
- Проверяйте размер бандла при добавлении библиотек

### 9. Тестирование и отладка

#### Тестовые пользователи
- `+79991234567` - клиент с особым поведением (ошибка бронирования)
- `+79990001122` - владелец парковки
- Используйте эти номера для тестирования специфичных сценариев

#### Отладка
- Используйте `console.log` для отладки (удаляйте перед коммитом)
- Проверяйте консоль браузера на ошибки
- Тестируйте на реальных устройствах через Telegram

### 10. Защищенные зоны

#### НЕ изменяйте без явного запроса:
- Базовую структуру `App.vue` (только добавление новых экранов)
- Систему аутентификации (`mockAuth.ts`)
- Основные типы и интерфейсы без согласования
- Логику деплоя и конфигурацию Firebase

#### Всегда спрашивайте перед:
- Удалением существующих файлов
- Изменением структуры проекта
- Добавлением новых зависимостей
- Изменением системы навигации

### 11. Коммиты и изменения

#### Перед внесением изменений
1. Прочитайте существующий код
2. Поймите контекст и зависимости
3. Проверьте, не нарушаете ли вы существующую функциональность

#### После внесения изменений
1. Проверьте линтер (`read_lints`)
2. Убедитесь, что нет TypeScript ошибок
3. Проверьте, что изменения не сломали другие экраны

### 12. Коммуникация

#### При неясностях
- Всегда уточняйте требования у пользователя
- Предлагайте варианты решения
- Объясняйте свои действия

#### При ошибках
- Сообщайте об ошибках сразу
- Предлагайте решения
- Не продолжайте работу с ошибками
