## Правила работы с защищенными зонами

### Перед изменением защищенной зоны:
1. **Всегда спрашивайте** у пользователя разрешение
2. **Объясняйте** что и почему вы хотите изменить
3. **Предлагайте альтернативы** если возможно

### При работе с частично защищенными зонами:
1. **Сохраняйте** публичный API
2. **Не ломайте** существующую функциональность
3. **Тестируйте** изменения на зависимых компонентах

### Исключения:
- Исправление явных багов
- Оптимизация производительности (с согласованием)
- Рефакторинг по явному запросу

## Чек-лист перед изменением защищенной зоны

- [ ] Получено явное разрешение от пользователя
- [ ] Понятна причина изменения
- [ ] Проверены зависимости
- [ ] Предложены альтернативы (если применимо)
- [ ] Запланировано тестирование
- [ ] Документированы изменения (если значимые)

## Контакты для вопросов

При сомнениях в изменении защищенной зоны - всегда спрашивайте у пользователя перед действием.
